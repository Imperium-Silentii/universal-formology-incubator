# Instruction: Co‑creator work cycle. Cloning and edits

## 🧭 Purpose

This document describes the main work cycle of a full participant of the Institution.

Your goal is not just to propose a worthwhile idea, but to **introduce a formal change into the body of our common project**, which will be reviewed, evaluated and, if approved, integrated.

This is the mechanism of your direct influence on the reality of Formology.

---

## ⚖️ Participation rule

*   Any GitHub user can **read and clone** the repository.
*   **Edits (Pull Requests) for consideration are accepted only from accounts that have the status of Scenic Citizenship.**

**The meaning of the rule:** Your contribution is an **asset**. It must be signed with your Stage Name to be accounted for in the overall economy of merits of the Institution. Anonymous proposals are not tokenized and are not considered.

---

## 🛠️ Algorithm of actions

### Step 0. (Mandatory) Legitimation
Obtain Scenic Citizenship and a title name. Without this step, the functionality of making edits is blocked for you.

[Instructions for obtaining citizenship](https://github.com/Imperium-Silentii/universal-formology-incubator/blob/main/welcome/0003-scene-name.md)

### Step 1. Cloning: Creating a local copy of the workshop
**Goal:** Get a complete, living copy of the entire repository on your computer for work.

1.  On the repository page, click the green button **`<> Code`**.
2.  Copy the URL.
3.  Open a terminal on your computer.
4.  Execute the command, pasting the copied URL:
    ```bash
    git clone https://github.com/your-username/universal-formology-incubator.git
    ```
    Now you have a local copy of the entire workshop.

### Step 2. Making changes: Working in your copy
**Goal:** Prepare a specific, isolated improvement.

1.  Create a new branch for your edit. This isolates your work:
    ```bash
    git checkout -b feature/name-of-your-contribution
    ```
2.  Make the necessary changes to the files in your local folder using any text editor.
3.  Save (commit) your changes with a clear description:
    ```bash
    git add .
    git commit -m "Description of the improvement or fix made"
    ```

### Step 3. Publication and Pull Request
**Goal:** Propose your changes for integration into the main project.

1.  Push your branch to the remote repository:
    ```bash
    git push origin feature/name-of-your-contribution
    ```
2.  On the repository page on GitHub, a notification about the new branch will appear. Click **`Compare & pull request`**.
3.  Fill out the Pull Request (PR) form:
    *   **Title:** Clearly and concisely formulate the essence of the proposal.
    *   **Description:** Describe in detail what you changed, what problem it solves, and what value it brings to the project.

### Step 4. Review and integration
Your PR will be reviewed by the leadership of the Institution. During the discussion, you may be asked to make additional edits. After approval, your PR will be merged with the main project branch.

**Your contribution will become part of Universal Formology.**
